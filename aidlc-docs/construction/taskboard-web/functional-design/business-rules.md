# ビジネスルール — taskboard-web

## BR-01 — 列の最小個数

- ボードは常に **少なくとも 2 列** を持つ（要件 3.1.1「複数列」）。
- **最後から 2 番目の列を削除しようとした場合**（削除後に 1 列未満になる場合）は **拒否** する。

## BR-02 — 列の追加

- 新規列は **末尾の `order`**（最大 +1）で追加する。
- 既定タイトルは `"New column"`（実装で i18n 可）。

## BR-03 — 列名の変更

- トリム後 **空** は不可。エラーはユーザーに示す（ストアは no-op または Result 型 — 実装選択）。

## BR-04 — 列の削除

- 削除対象列に **カードが 1 枚以上** ある場合: それらを **表示順で左隣の列**へ移す。左端の列を削除する場合は **右隣**へ移す（実装で一貫すればよい — ここでは **常に order より小さい側の存続列** が無ければ **order+1 の列** へ移動）。
- より単純な既定: **削除列のカードは `order` が次に小さい列へ**、対象が左端なら **次に大きい列へ**。
- BR-01 を満たすため、**2 列のみのときは列削除不可**（カード有無にかかわらず）。

## BR-05 — カードの追加

- `title` トリム後 **1 文字以上**。
- 必ず **既存の columnId** に紐づける。

## BR-06 — カードの編集・削除

- 編集: `title` は BR-05 と同様に空不可。
- 削除: 存在する `cardId` のみ。

## BR-07 — 永続化

- **保存**: 常に現在の `BoardSnapshot` 全体を JSON にシリアライズ。
- **読込**: JSON が **スキーマ不正** または **不変条件違反** の場合は **フォールバック**: 既定の 2 列（例: To Do / Doing）と空カードで初期化し、オプションでユーザーに通知（実装）。

## BR-08 — 同時実行

- 単一タブ想定。`storage` イベントによる他タブ更新は **任意**（MVP では未対応でもよい）。
