# ビジネスロジックモデル — taskboard-web

## 1. ユースケースと操作

ドメイン操作は **純粋関数** として表現可能な部分（スナップショット → 新スナップショット）と、**副作用**（Repository）に分離する。

| 操作 | 入力 | 結果 |
|------|------|------|
| 初期化（空ではない既定ボード） | なし | `BoardSnapshot`（2 列・カード 0） |
| 列追加 | 現在スナップショット | 新スナップショット |
| 列改名 | `columnId`, 新タイトル | 新スナップショット |
| 列削除 | `columnId` | 新スナップショットまたは **エラー**（BR-01, BR-04） |
| カード追加 | `columnId`, タイトル, 本文任意 | 新スナップショット |
| カード更新 | `cardId`, 部分更新 | 新スナップショット |
| カード削除 | `cardId` | 新スナップショット |
| シリアライズ | `BoardSnapshot` | JSON 文字列 |
| デシリアライズ | JSON 文字列 | `BoardSnapshot` または **エラー**（BR-07） |

## 2. 状態遷移の概要

- すべてのミューテーションは **BR-01〜BR-07** を満たすスナップショットにのみ遷移する。
- **不正な中間状態**は公開しない（Either / Result で表すか、no-op）。

## 3. Testable Properties（PBT-01）

以下は **プロパティベーステスト** の候補とカテゴリ（`property-based-testing.md` の分類）。

### 3.1 Round-trip（PBT-02）

| ID | 対象 | プロパティ |
|----|------|------------|
| TP-RT-1 | `serialize` / `parse`（JSON） | 任意の **有効な** `BoardSnapshot` について `parse(serialize(s))` は `s` と**構造的に等価**（深い等価）。 |
| TP-RT-2 | Repository | `load` が `save` の直後に呼ばれたとき、**同一スナップショット**が得られる（ストレージモック使用可）。 |

### 3.2 Invariant（PBT-03）

| ID | 対象 | プロパティ |
|----|------|------------|
| TP-INV-1 | 列削除後 | 全カードの `columnId` は依然として存在する列を指す。 |
| TP-INV-2 | 任意のミューテーション後 | 列数 ≥ 2、列 `order` は 0..n-1 の順列。 |
| TP-INV-3 | カード追加後 | カード枚数はちょうど 1 増加し、他カードの id は不変。 |

### 3.3 Idempotence（該当時）

| ID | プロパティ |
|----|------------|
| TP-ID-1 | **同一スナップショット**を連続 `save` しても、読み出し結果は変わらない（上書きの冪等性）。 |

### 3.4 ジェネレータ要件（PBT-07 準拠の方針）

- **有効スナップショット**ジェネレータ: BR の不変条件を満たす `BoardSnapshot` をランダム生成。
- **操作**ジェネレータ: 列削除・カード移動など、許可操作列からランダム選択し **縮小（shrink）** で最小反例を探索。

## 4. 明示的に PBT 対象外とするもの

- **他タブ同期**（BR-08 任意）。
