# 要件定義書 — TaskBoard Mini

## 1. 意図分析サマリー

| 項目 | 内容 |
|------|------|
| **ユーザー要求** | タスクボードの作成（静的ホスト可能な Vue アプリ、ブラウザ保存、列とカードの基本操作） |
| **要求タイプ** | 新規プロジェクト（Greenfield） |
| **スコープ見積** | 単一フロントエンド構成（バックエンドなし）、複数コンポーネントに分けうるが同一リポジトリ内 |
| **複雑度見積** | 中程度（UI・状態管理・永続化・PBT による検証義務） |

---

## 2. 背景と目的

同一ブラウザ内でカンバン風の列とカードを管理し、**サーバー不要**でホスティングできるタスクボードを提供する。初版は操作を絞り、**静的ファイル配信**で運用できることを目指す。

---

## 3. 機能要件

### 3.1 必須（初版スコープ）

1. **列（ステータス列）**
   - 複数列を表示する（例: To Do / Doing / Done のような既定セットでも、列名の編集ができる構成でもよいが、**少なくとも複数列**が存在すること）。
   - 列の追加・削除・名称変更の要否は実装設計に委ねるが、**カードを区分できる列**が必須。

2. **カード（タスク）**
   - カードの追加・編集（タイトルまたは本文など最低限のテキスト）・削除。
   - 各カードはいずれか**1 つの列**に属する。

3. **データ永続化（ブラウザのみ）**
   - ページ再読込後も状態を復元する。
   - 保存先は **`localStorage` または `IndexedDB`** のいずれか（選定は設計・実装段階）。**外部サーバーへの保存は不要**。

4. **配布形態**
   - **バックエンド不要**でビルド成果物を静的ホスティングできること（CDN・オブジェクトストレージ・GitHub Pages 等を想定）。

### 3.2 初版で含めない（明示的アウトオブスコープ）

- カードの**ドラッグ＆ドロップ**による列間移動（質問回答 Q4: A）。
- **複数ボード**の切り替え、**ユーザー認証**、**複数ユーザー共有**（必要になれば別リリースで検討）。

### 3.3 技術的拘束（質問回答に基づく）

- **フロントエンド**: **Vue**（ビルドは Vite 等、詳細は設計・コード生成で確定）。
- **セキュリティ拡張（Security Baseline）**: **適用しない**（PoC・プロトタイプ志向。本番公開時は別途ハードニングを検討）。

---

## 4. 非機能要件

### 4.1 品質・テスト（必須）

- **プロパティベーステスト（PBT）**: 拡張ルールを **フル適用**（`property-based-testing.md`）。  
  - ビジネスロジック・データ変換・シリアライズ／デシリアライズ等に対し、設計段階で**テスト可能な性質**を特定し、実装では **PBT と例示ベースのテストを併用**する。  
  - 具体的なルール ID・検証観点は Construction の Functional Design / Code Generation で追従する。

### 4.2 パフォーマンス・規模

- 個人〜小チーム利用を想定し、**数百枚程度のカード**まで現実的に操作できること（厳密な数値 SLA は初版では定めない）。

### 4.3 互換性

- **モダンブラウザ**（最新の Chrome / Firefox / Safari / Edge の各最新系）を対象とする。

### 4.4 セキュリティ

- Security Baseline はオフのため、**公開ネットワークに載せる場合は XSS・内容の機密性**等を別途レビューすることを推奨（要件としての必須ルールとはしない）。

---

## 5. 前提・制約

- ワークスペースは **Greenfield**、既存アプリケーションコードなし。
- アプリコードは **リポジトリルート**に置き、`aidlc-docs/` はドキュメント専用。

---

## 6. 用語

- **列**: カンバン上の縦の区画（ステータス等）。
- **カード**: 列に属する 1 件のタスク表現。
- **PBT**: ランダム入力と不変条件に基づくテスト手法（拡張ルールに従う）。
